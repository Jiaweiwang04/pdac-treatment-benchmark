# PANC 原始数据处理规则 v2.0

版本：v2.0  
更新日期：20260910  
状态：第一阶段已实现并核查；时间轴与决策点质量分层待完成。

## 目的与范围

明确原始数据包含什么、如何连接、哪些信息缺失，以及病理能否逐标本完整保留。第一阶段建立全量方案开始记录登记，不判定最终训练／测试可用性，不生成治疗适用性标签。

方法及阶段报告按[GA01第4节和第6节](../standards/ga01_research_workflow.pdf)要求记录来源、处理及验证；原始数据与派生结果分离遵循[GA09第2.1节](../standards/ga09_data_code_management.pdf)。

## 输入及来源

| 输入 | 使用方式 |
| --- | --- |
| PANC 1.0-public全部发布文件 | 清点相对路径、大小及SHA-256，不修改原文件 |
| 十张临床CSV | 按发布原字段读取，检查表结构及复合键 |
| 源路径配置 | 使用[source.json](../../../code/config/v2.0/source.json)指定的目录和发布版本 |
| 原始指南及变量字典 | 后续核实字段含义与时间锚点；尚未完成的语义解析不写成已验证 |

运行程序及配置位置见[项目入口](../../../README.md)。[原文件清单](../../../code/results/v2.0/01_source_audit/source_inventory.json)保存本批输入的校验和，文件总数不等于临床表数量。

## 原始值保留

每个临床单元格按原始字符串保留，包括空字符串、Unknown、Not applicable、0和遮蔽编码。空白不改成阴性，数值字符串不在保真层改类型；用于计算的数字另行解析。

按CSV规范读取逗号、引号和嵌入换行，保留原有LF或CRLF。重复表头、空表头或行宽与表头不一致直接报错，不能以截断、补列的方式掩盖问题。

每条导出记录包含来源文件、文件校验和、主键字段和值，以及逻辑行号。逻辑行号从表头为第1行起算，不一定等于包含多行文本时的物理行号。

## 主键与关联

| 层级 | 复合键 |
| --- | --- |
| 患者 | cohort、record_id |
| 癌症 | 患者键＋ca_seq |
| 病理报告 | 患者键＋path_proc_number＋path_rep_number |
| NGS检测 | 患者键＋cpt_number |
| 系统治疗 | 癌症键＋regimen_number |
| 放疗 | 癌症键＋rt_number |
| 影像、医生评估、血清标志物 | 患者键分别加scan_number、md_visit_number、tm_number |

重复主键、缺失主键、患者或癌症关联不唯一，以及NGS到病理的关联问题逐条记录。程序不以“只取第一条”消除问题，关联异常也不导致原始行消失。病理原表没有ca_seq，不能仅凭患者相同就把所有报告认定为目标癌症证据。

## 病理报告与标本

逐报告保留全部原字段，从30个可能的槽位展开所有已填标本。每个标本分别保存部位、癌种、浸润癌及其组织学、原位癌及非浸润组织学。槽位任一字段有值就保留，并与报告声明的标本数核对。

阴性、其他癌症和后续标本均保留在全程数据层。腺癌NOS不自动改写成导管腺癌；本阶段不借用后续NGS替较早时点确诊。PD-L1、MSI、MMR及ER/PR/HER2的原字段完整保留，其逐次检测和报告日期解析尚待完成。

取材日不等于病理主体报告签发日。未知的可用时间保持未知；不能要求专家确认一个公开数据本身无法证明的事实后就默认为可用。后续按任务要求区分可确认、需补充证据和无法确认的情况。

## 治疗记录与时间换算

完整登记目标及非目标癌症的全部方案，保留各药物原名、方案序号及原日期。方案序号不等于治疗线数，增加、减少或维护药物不自动意味着进展后换线。

方案日期相对于所属癌症诊断日。统一时间轴时，计算“原方案间隔＋所属癌症诊断日－患者第一个目标癌症诊断日”。任一所需日期缺失，派生日也保持缺失；负数和真实0均允许保留。

同患者、同癌症、同开始日的多记录只标记待核查，不直接合并或删除。实际采用的药物属于观察事实，不能直接用来证明治疗最优。当前登记表中所有记录的training_test_eligibility均为not_evaluated。

## 验证及失败处理

导出后重新读取原CSV，与JSONL逐行比较全部字段和原值。运行结束前再次核对原文件SHA-256。关键行为检查覆盖复杂CSV、缺失与0、复合键、跨癌症时间换算、阴性标本和第30槽位。

出现重复或缺失主键、病理标本数不一致、原文件变化时，审计标为failed并非零退出。关联问题保留为completed_with_issues；这并不等于可进入下游训练。解析或字段保真异常会使命令非零退出；若运行清单仍为running，说明中途异常退出，不能据已有部分文件认定完成。

具体结果见[审计报告](source_data_audit_report_v2.0.md)。规则有变更时，应同步实现、检查和本文件，再重新生成受影响产物。
