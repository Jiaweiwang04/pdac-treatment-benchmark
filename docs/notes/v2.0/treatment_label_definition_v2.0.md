# 治疗方案标签定义与审核说明 v2.0

版本：v2.0

更新日期：20260915

状态：四类主标签及研究属性定义有效；Pilot预拟标签已生成，专家审核与裁定尚未完成。

## 目的与标注对象

每条标签回答：**在该患者的这个候选决策时点，根据允许使用的患者资料，以及知识截止日之前的指南与论文，这个候选治疗方案在 Track A 范围内是否匹配？**

标注单位为“候选决策点 × 候选治疗方案”。同一个决策点可以对应多个方案，也可以有多个得到支持的方案；不预设唯一正确答案。患者、决策点和方案分别保留编号。主标签评价证据匹配关系，不评价该患者一定有效、不估计疗效大小，也不直接表示方案之间的优先顺序。

本轮评价病理及癌症归属、分子结果、疾病情境、既往治疗及相关时间信息。不以一般临床耐受指标的缺失排除候选，不推定已经完成个体安全性或剂量可行性评价。

当前候选基线为952条主候选、602个进展扩展组、244条治疗调整附录，详见[候选集合报告](candidate_cohort_report_v2.0.md)。标签定义不会把扩展组、附录或待核查记录自动提升为主集合或最终训练样本。

## 四类主标签

使用下列稳定代码；它们是类别，不是从高到低的数值评分。

| 代码 | 中文名称 | 具体含义 | 必须提供的理由 |
| --- | --- | --- | --- |
| `SUPPORTED` | 支持匹配 | 在明确的使用情境下存在可引用的适用依据；现有允许使用的患者事实满足关键Track A条件，未发现已知的实质性冲突。 | 支持哪一种使用情境、相应证据、已满足的关键条件及患者资料来源。 |
| `CONDITIONAL` | 条件性匹配 | 有明确、可引用的适用路径，但决定匹配关系的具体Track A条件尚未确认；若这些条件成立，该路径可支持匹配。 | 明确写出“如果什么条件成立，则如何匹配”，并列出未知条件、对应证据及对标签的影响。 |
| `MISMATCH` | 有依据不匹配 | 在本次所评价的使用情境中，已知患者事实与有证据支持的关键适用条件存在明确且实质性的冲突。 | 哪条适用条件、哪项已知事实、为什么构成冲突，以及双方来源。 |
| `INDETERMINATE` | 无法判定 | 缺乏足够患者资料或可解释的适用证据，或存在未解决的实质性矛盾，无法可靠形成以上判断。 | 是患者资料不足、证据不足、时间／归属不明还是证据冲突；说明缺口影响什么判断。 |

“支持匹配”只在本项目的Track A范围和已注明的使用情境内成立，不能缩写为“临床上一定应该使用”。“有依据不匹配”也不等于该药永远无效或任何情况下禁用。

尚未开始标注时，主标签为 `null`；`null` 不等于“无法判定”。只有完成资料与证据审阅、仍不能确定时，才标 `INDETERMINATE`。

## 判定顺序与边界

1. 确定候选点、方案身份、癌症归属以及要评价的使用情境；辨明这条记录属于主候选、扩展组还是附录。
2. 按患者时点截断资料。建立每项关键患者事实的原文、来源和时间状态，未来信息不能补进早期候选。
3. 查找该方案在相应情境下的指南／论文依据，提取适用人群、条件、研究设计和原始证据等级。未完成检索不能写成“没有证据”。
4. 对照关键条件逐项记录“已满足、已知不满足、未知、证据冲突”。资料不足不是已知不满足；一般性“无反对证据”不是支持证据。
5. 形成上述四类之一，并写出能够由另一位审核者复查的理由。多条证据支持不同路径时，逐路径保留，不能因某一条路径不适用就把整个方案判为不匹配。

**条件性匹配与无法判定：**前者必须已经找到明确的适用路径，并能列出有限、具体、可核对的未知条件；后者是适用依据本身不清、方案或癌症情境无法可靠识别、未知条件无法收敛，或证据矛盾无法解释。不能用一句“临床条件允许时可用”把所有不确定方案都标成条件性匹配。

**有依据不匹配与无法判定：**前者需要已知事实和明确适用条件之间的冲突；仅未查到论文、没有检测某标志物、未记录某治疗史或患者实际没有使用，均不足以给出不匹配。

**研究性与证据强度：**研究属性和证据强度独立于主标签。研究方案不能因为“有论文”就自动获得支持匹配，证据较弱也不能自动等同于有依据不匹配。

**证据冲突：**先核对指南版本、适用人群、治疗阶段和研究背景是否不同。能够解释的差异分别记录；不能解释、且会改变主标签的冲突进入待裁定状态。若无法形成可靠判断，主标签为无法判定，不自行制定未经确认的指南优先级。

## 研究性方案的标记

确认纳入研究性方案，但必须显式标注。每条“决策点×方案”记录使用独立的 `use_context` 字段：`routine`（常规使用情境）、`research`（研究性使用情境）；尚未完成证据判定时为 `null`。常规／研究属性需有对应情境下的依据，不根据药名、是否上市或有无论文简单推断。同一药物在不同情境下可以有不同属性。

研究性记录在候选表和专家审核包中显示醒目的“研究性方案”。其匹配判断表示**在明确的研究性使用路径下**是否有证据支持讨论该候选，不表示已确认为常规标准治疗，也不表示患者满足临床试验的全部入组条件。试验是否招募、地点、可及性和完整入组条件另行记录；本阶段不作默认肯定。

若同一候选方案存在常规与研究两种适用路径，分别记录路径证据及条件；需要拆分标注记录时用 `assessment_context_id` 区分，不能覆盖成一个含义不清的标签。对外展示和后续统计保留研究标记，不能把研究性支持直接计作常规治疗推荐。

## 缺失信息与时间规则

| 情况 | 处理规则 |
| --- | --- |
| ECOG、常规肝肾功能、剂量或完整毒性资料缺失 | 记入Track B评价范围限制，不单独触发条件性匹配、无法判定或不匹配。不得补成正常。 |
| 关键Track A适用条件未知 | 有明确适用路径和具体未知条件时可为条件性匹配；否则无法判定。 |
| 关键检测未做、覆盖范围不明或结果未记录 | 保持未知，不能当作检测阴性。分子结果还需核对样本、面板及具体变异含义。 |
| 病理取材在先、主报告时间未确认 | 保留“取材在先、报告可用时间未确认”。不能改写为确定当时已知；其是否影响标签取决于该判断是否依赖此报告。 |
| NOS病理与在先PAAD编码 | 按既有候选规则保留其证据与限制，不改写为明确导管亚型；若某候选方案依赖尚未确认的具体组织学，需反映到条件或无法判定原因。 |
| NGS报告同日、晚于t0或日期关联不清 | 不作为已确认的在先NGS。不得用未来报告支持早期标签。 |
| 同日进展与治疗开始 | 不假定进展在治疗之前；同日顺序未知的事实不能直接作为当前用药的事前依据。 |
| 既往疗效或进展 | 只有在当前候选之前已可用、且癌症归属可解释的事实才能用于当前病史；当前治疗之后的反应留在结局参考。 |
| 全程原病理字段、后续随访和结局 | 用于追溯，不整体作为时点输入。全字段保留不等于所有字段在t0均可使用。 |

时间规则沿用[候选决策点协议](decision_point_protocol_v2.0.md)，本文件不放宽NGS严格在先要求，也不通过改动t0获得更多分子证据。关键时间可用性存在不确定且会影响标签时，必须明确记录，不能在摘要中隐去。

## 知识截止日与证据要求

知识截止日固定为 **2026-09-12**，该日期是本轮允许使用知识的上限，不代表已经检索完毕。

患者信息时间与知识时间分别管理：可以用截止日之前的新知识重评历史病例，但患者资料只能来自其候选时点允许使用的信息。截止日之后才公开的材料不作为本轮标签依据。记录指南版本／更新日期、论文公开日期、实际检索日期及页码／表格定位；不能仅因今天能打开某网页，就推定网页现有内容在截止日已经存在。公开时间无法核实时标为待核实，不悄悄纳入已确认的证据集。

历史实际方案仍是候选来源之一，但不是正标签。分别保存其同期依据和本轮截止日依据；同期合理性只作独立历史说明，不能替代当前知识框架下的主标签。找不到同期来源时诚实记录“未检得／未完成核查”，不补造引用。无实际用药记录的候选也可获支持；观察到后续获益或失败都不能直接决定主标签。

每条证据至少保存：来源标识、指南／论文名称与版本、机构或作者、公开日期、链接或DOI、可定位的章节／页码／表格、适用人群、方案及治疗情境、关键条件、原始推荐或证据等级、支持／限制／冲突方向，以及本病例的对应关系。保留原始分级体系；本轮未批准把不同指南和论文等级强行换成一个统一分数。

本文件是项目方法定义，不是治疗指南，不提供具体药物的临床适用性结论。下节案例为虚构逻辑示例；真实方案标签必须补充相应权威指南或论文和患者来源。

## 边界案例

下表中的“方案A、条件X、检测Y”均为虚构占位符，不对应具体药物或医学事实。

| 场景 | 应如何标注 | 原因 |
| --- | --- | --- |
| 证据明确支持方案A的使用路径，所需Track A条件均有在先资料支持；ECOG未记录 | 支持匹配；另记Track B限制 | 主标签不是完整临床安全性结论。 |
| 证据要求条件X；其余关键条件明确满足，但X尚未确认 | 条件性匹配；条件写为“需确认X” | 有明确适用路径和可核对的具体缺口。 |
| 检测Y未记录，证据要求Y满足某条件 | 不能仅据此标有依据不匹配 | 未记录不等于已知阴性或不满足。 |
| 已知在先事实明确不满足方案A的一项必要条件，且未找到能够解释该冲突的其他支持路径 | 有依据不匹配 | 必须引用必要条件和患者事实双方来源。 |
| 药物身份被遮蔽，无法可靠识别方案及适用依据 | 无法判定 | 尚无可评价的明确对象；不能猜测药物身份。 |
| 只有一篇探索性论文，尚不能说明患者条件与研究人群的对应关系 | 研究性方案＋无法判定 | 研究属性不是支持标签；存在论文不等于匹配成立。 |
| 研究性路径的依据和Track A对应关系均明确，但试验可及性未知 | 可为研究性方案＋支持匹配；另列可及性未知 | 只支持研究路径下的证据匹配，不宣称能够入组或作为常规治疗。 |
| 指南或论文的实质性结论冲突，当前无法解释 | 无法判定；审核状态记为存在分歧或待审核 | 主标签和审核状态分别记录，后续保留裁定过程。 |
| 方案实际使用后获益，但决策时点的适用依据尚未建立 | 不因结局升级主标签 | 用药与结局属于独立参考。 |
| 支持某匹配关系的NGS报告在候选日之后才到达 | 不使用该未来结果 | 当前知识重评不允许未来患者信息泄漏。 |

## 结构化字段与专家审核

下列字段构成标注记录的解释要求；字段适用于预拟标签、独立审核与裁定；各阶段分别保存。

| 字段 | 含义与要求 |
| --- | --- |
| `patient_key`、`candidate_id`、`t0_day`、`candidate_role` | 患者、候选时点及所属集合；沿用既有来源，不重新编号或移动日期。 |
| `regimen_id`、`regimen_display_name` | 候选方案的稳定编号及可读名称；原始药名和规范化映射另存。 |
| `assessment_context_id`、`use_context` | 此标签所评价的具体使用情境，以及常规／研究属性。 |
| `proposed_label`、`reviewed_label` | 四类主标签之一；初标与专家审核结果分别保存，未标注为null。 |
| `matched_conditions`、`unmet_conditions`、`unknown_conditions` | 关键条件逐项核对；每项关联证据及患者资料，不只写一句总评。 |
| `conditional_statement` | 条件性匹配必填，说明未知条件成立时支持什么使用路径。 |
| `mismatch_reason` | 有依据不匹配必填，明确必要条件与已知事实之间的冲突。 |
| `indeterminate_reason` | 无法判定必填，区分证据不足、身份不明、患者资料不足、时间／归属不清或证据冲突。 |
| `rationale`、`evidence_ids`、`patient_fact_refs` | 可读解释、指南／论文引用和患者原记录定位。所有已赋值标签均需解释；未检得证据也需记录检索状态。 |
| `scope_limitations`、`temporal_limitations` | Track B范围限制及会影响解释的患者资料时间限制。 |
| `evidence_cutoff_date`、`label_definition_version` | 固定知识截止日2026-09-12及本文件版本v2.0。 |
| `observed_regimen`、`historical_evidence_refs` | 是否历史实际方案及其同期依据；不得用作自动正负标签。 |
| `review_status`、`reviewer_id`、`reviewed_at`、`review_comment` | 审核状态、审核者、时间及意见；与主标签分开。 |

专家审核至少核对：方案及使用情境是否清楚；研究属性是否正确；患者关键事实及病理是否完整呈现；证据是否支持本情境；条件与冲突是否有来源；四类标签选择是否恰当。审核者可确认、修改标签或指出分歧；原初标、原证据与修改记录保留，不能以最新值覆盖审核历史。

审核状态使用“待审核、已审核、存在分歧”。“已审核”表示完成记录中的审核动作，不自动等于专家一致或金标准。专家人数、独立审核安排和分歧裁定方法尚未确定，需在pilot实施前讨论，不预设多数票或单人裁定。

`INDETERMINATE` 不作为负标签；`CONDITIONAL` 不自动映射为正或负；四类主标签不自动映射成优先排序。后续训练目标、二分类映射或评估合并如有需要，另行明确，不能在导出时静默转换。研究性方案及主集合／扩展组属性持续保留。
